# PathSnap: distributed map matching and route reconstruction

PathSnap maps noisy GPS observations to directed road arcs, compares several candidate-ranking models, and applies a graph-aware Viterbi decoder to improve route continuity. The project includes training, trip-level cross-validation, Bayesian tuning, a FastAPI backend, a browser UI, dataset inventory, and Folium maps.

## Data layout

The supplied archive is extracted to `data/Student folder/`:

```text
data/Student folder/
  train/         80 labeled training trips
  student_test/  10 labeled development trips
```

Each trip contains `.track` (longitude, latitude, timestamp), `.nodes` (longitude, latitude), `.arcs` (from-node, to-node; row index is arc ID), and `.route` (reference arc sequence). The provided package has no separate evaluator-test partition. The application defaults to the ten `student_test` trips; set `PATHSNAP_TEST_PARTITION` and `PATHSNAP_DATA_ROOT` to point to a separately supplied evaluator partition when one becomes available. Keep its labels server-side and do not use it for model selection.

## Install and train

From the project directory in PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python train.py --trials 3
```

If the `py` launcher is unavailable, use Python 3.12 in place of `py`. The pinned environment matches the saved model artifact. Training inventories the data, compares Logistic Regression, Random Forest, Extra Trees, histogram gradient boosting, and XGBoost using three-fold `GroupKFold` cross-validation over whole trips, selects by cross-validated observation-level top-1 accuracy, then tunes that model with Optuna's TPE Bayesian sampler. The ten supplied development trips are used only after model selection to compare model and decoder behaviour. Fixed seed: `2718`.

Training outputs are written under `artifacts/`:

- `results.json`: actual per-model CV and student-test metrics, configurations, timing, candidate miss rates, and classifier/HMM comparisons.
- `bayesian_trials.csv` and `best_params.json`: search record and selected parameters.
- `model.joblib`: fitted model used by the API.
- `exploration/`: dataset inventory, summary, and EDA map.
- `maps/`: a Folium map with GPS, road graph, reference route, and predicted route.
- `model_comparison.png`: plot generated from the saved CV and student-test metrics.

Candidate rows represent `(GPS observation, directed road arc)` pairs. The label is the nearest generated candidate arc appearing in that trip's reference route. Features include geodesic-scale local distance/projection, motion direction and speed, timestamp gap, arc geometry, and road-node degree. Candidate search uses a 180 m local spatial index and keeps up to 36 arcs per observation. Training keeps the positive candidate, nearby hard negatives, and sampled alternatives. For model comparison, classification precision/recall/F1/log loss are computed on candidate pairs; top-1 accuracy is measured per GPS observation and macro F1 is candidate-pair macro F1.

## Run the API and interface

```powershell
python -m uvicorn api:app --host 0.0.0.0 --port 8000
```

Open `http://localhost:8000/ui/` or `http://localhost:8000/` on the server laptop. From a second laptop, open the server's LAN address on port 8000, or serve the `ui/` folder there and enter the API host address in the interface. The API provides `/health`, `/trips`, and `POST /predict/{trip_id}`. It sends observations and predicted route geometry to the browser; its response includes aggregate evaluation metrics only, not reference route IDs or reference geometry. API request logs are printed to the server console.

Configure a separate data root and partition with environment variables before starting the server:

```powershell
$env:PATHSNAP_DATA_ROOT = 'C:\path\to\data\Student folder'
$env:PATHSNAP_TEST_PARTITION = 'evaluator_test'
$env:PATHSNAP_MODEL = 'C:\path\to\artifacts\model.joblib'
python -m uvicorn api:app --host 0.0.0.0 --port 8000
```

The UI loads Leaflet and OpenStreetMap tiles from their public hosts, so those map layers need network access in the browser. The prediction API and model inference run locally.

## Integrity and scope

Training and student-test metrics are generated by executable experiments, not entered by hand. Reference route labels are used to construct training targets and server-side evaluation metrics. They do not enter model features or the UI response. The supplied assessment policy requires teams to understand, verify, and be prepared to explain their own implementation and results. AI assistance should be disclosed as required by the event's policy. This repository contains the working project; the separate final technical report and GitHub publication are intentionally outside this work.
